Index naming audit — 2026-10-22

Applied convention: Foo is a type, foo is an object, foos is a collection,
and iFoo is an index. Data members keep the leading underscore.

Backend changes:
  FileRecordingBackend: _slot -> _iSlot; lastSlot -> iSlotLast.
  Slot-list loops: index -> iSlot. Filename character loop: digit -> iCharacter.
  Statistics/Snapshot: _file -> _fileNumber (one-based display number, not a file object).

Left unchanged intentionally:
  Counts such as _completedBins and _count remain counts, even when used to append.
  Byte offsets, timestamps, rates, bit masks and lookup values keep their meanings.
  RecordingStatus field enums and JavaScript object keys are named fields, not object indices.
  Slot/slot/_slots, write, and both verify overloads remain unchanged.
  SDK APIs, serial messages, JSON fields, filenames and on-disk layouts are unchanged.
  Generated build output and third-party dependencies were excluded.
